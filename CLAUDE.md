# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

A tablet-first React app (Vite + TypeScript, no backend) for playing the solo print-and-play card game **Grimm World**. Game rules are in `game-files/Grimm World - The Rulebook.pdf`; the card sheets are in `game-files/GrimmWorld_ENG_BaseGame_9_Cards_A4.pdf` (628 MB, not something to open casually). `README.md` documents the player-facing controls and rules the app enforces — keep it in sync when behaviour changes.

## Commands

```bash
npm run dev -- --host        # dev server on :5173, reachable from the tablet on the LAN
npm run build                # tsc -b + vite build
npx tsc -b                   # type-check only
npm run lint                 # oxlint
uv run scripts/split_cards.py    # PDF → public/cards/{lg,sm}/NNN-{front,back}.webp + cards.json (~1 min)
uv run scripts/index_cards.py    # OCR card types/numbers into cards.json (~15 min; --cards 120,130 to redo a few)
uv run scripts/split_rules.py    # rulebook → public/rules/ page images + rules.json (~15 s)
uv run scripts/make_icons.py    # PWA icons → public/icons/ (committed; from the title card)
uv run scripts/split_booklets.py # rule booklets → public/booklets/ page images + booklets.json (~1 min, OCR)
npm run release              # commit-and-tag-version: bump version, update CHANGELOG.md, commit, tag (--dry-run to preview)
```

There is no test suite. Verify UI changes in a browser with the `playwright-cli` skill (tablet size: `resize 1180 820`). The table state is autosaved in `localStorage` under `grimm-world:table:v1`; clear it (`localStorage.clear()`) to start from the initial setup.

`public/cards/`, `public/rules/` and `public/booklets/` are generated and git-ignored. Python scripts use PEP 723 inline dependencies — run them with `uv run`, not pip/venv (the system Python has no pip).

## Card data pipeline

- `split_cards.py`: each PDF page is one 300 dpi JPEG with a centred 3×3 grid of 63.5×88.9 mm cards. Odd pages are fronts, even pages backs, **mirrored left↔right** (back of (row, col) is at (row, 2−col)). Card ids `001`–`540` follow sheet order. It crops the embedded JPEG (no re-render).
- `index_cards.py` adds `type`, `code` (e.g. `Y291c`, `B23`, `X05`, `T07`, `R1-111`) and `name`. Card ranges per type, Region/Terrain numbers and hand-verified OCR corrections (`KNOWN`) are hardcoded for this specific PDF. Fronts are the reliable OCR source; backs are only a cross-check.
- The app only needs `public/cards/cards.json` plus the images; card types drive the deck setup, deck/area rules and search. The title card (`type: 'title'`) is excluded from play (`playableCards`).
- `split_rules.py`: the rulebook has no PDF outline and its extracted text loses the inline game symbols, so the app shows page images and uses text only for search. `rules.json` holds per-page text and a table of contents parsed from the Contents pages, with each heading's page and vertical position (`y`). Printed page N is PDF page N+1 (page 0 is the cover).
- `split_booklets.py`: `GrimmWorld_ENG_RuleBooklets_A4.pdf` has six fold-up mini booklets ("The Encyclopedia"), one per page, each a 300 dpi JPEG with a 4×2 grid of card-sized panels (`GRID_*`, hardcoded for this PDF). The top row is upside down: page 2, page 1, front cover, back cover; the bottom row is pages 3–6. `cut_out()` makes the printed paper around the book transparent and its shadow a see-through black one (`B-P.webp` are RGBA); the paper must match the paper's colour balance closely, since the silver corner pieces are as grey as the shadow. The book's outline takes the colour just inside it (no light fringe), and the panel's outermost pixels are always transparent (the sheet's fold lines run there). Covers have no printed shadow; CSS adds one (`img.cover`). Each page also records where the book lies across it (`body`: the frame, `extent`: with the corner pieces) — left and right pages have the paper on opposite sides and the covers are wider — so `BookletScroll` can line the pages up one below the other. Outputs `B-P.webp` (P = 0 front cover … 7 back cover) and `booklets.json` (titles hardcoded — blackletter — and per-page OCR text, with lost spaces restored by `wordninja`, for search).

## App architecture (`src/`)

**State.** `store.ts` is a tiny external store (`useSyncExternalStore`) holding one immutable `Table` with undo/redo history and debounced localStorage autosave. All mutations go through `update(fn)` where `fn` is a pure `(Table) => Table` from `actions.ts`; returning the same object means "no change" (no history entry). `update` also runs `settle` (`settleSpots` + `settleLayout`) on the result, so table-wide layout invariants hold whatever action ran. View state (pan/zoom, selection, dialogs, drag hover) lives in React state in `App.tsx`, not in the store.

**Table model** (`types.ts`):
- `stacks: Record<id, Stack>` — every pile of cards, wherever it is. `Stack.cards` is ordered **bottom → top** (top card = last element).
- `z` — ids of stacks lying on the table, back to front. `dock` — ids of the sidebar decks, in sidebar order. `tray` — ids of the piles set aside in the right sidebar (`Tray.tsx`), top to bottom; their `x, y` and `rot` mean nothing there (`toTray` / `fromTray` in `actions.ts`). A stack is in exactly one of them.
- `Stack.deck` marks a fixed deck (`DeckKind`), in the sidebar or on the table; `Stack.slot` marks the storybook's two fixed table places (`story` face-down deck, `story-revealed`). Deck and slot stacks (`isFixed`) stay when empty and never move (a drag on a table deck takes its top card); plain table piles are removed when their last card leaves (`withCards` in `actions.ts` enforces this and also records `origin`).
- `origin` — the deck each card last came out of; `battlefield` — the on-demand battlefield area; `tokens` — figures (`tokenSize()`: the Player marker, the only cube, is smaller). Figures belong to no area or spot: they're added at the screen center on whatever lies there and dragged anywhere, with no `placement()` check; `settleLayout()` moves them with the area they lie in.
- Table coordinates are world units: a card is `CARD_W × CARD_H` = 250 × 350 (`cards.ts`); the view is a CSS transform of the world div. Region Cards are landscape (`isLandscape()`): a stack's `x, y` is still a portrait card's place, and `cardBox()` draws the card across it with the same center, so hit-testing, stacking and area checks need no special case. Their images are turned by CSS (`.landscape`, front a quarter left, back a quarter right with `.turned-right` — `landscapeClass()`); they never rotate. Cards on a spot with `turn` are drawn the same way (`turnedClass()`). `useFlip.ts` animates turning a card over (about the horizontal axis for landscape cards). A stack's `rot` is the CSS `rotate` property, leaving `transform` free for that animation.

**Rules modules** — the game logic the UI must respect:
- `decks.ts`: the fixed decks (`DECKS`; `SIDEBAR_DECKS` excludes the storybook, the Encounter Deck and `TABLE_DECKS` — Quest, Enemy, Training Deck and Banned Cards, which lie on the table, each on its place in its own area, `deckPlace()`), what each may `holds`, how returned cards are inserted (`top` / `bottom` / `sorted`), and `homeDeck()` (origin deck if it may hold the card, else the default deck for the card type). `deckStack()` finds a deck's pile; the Encounter Deck lies on one of two places (below), the one with more cards. Any drop on the sidebar returns cards to their home deck; deck-to-deck drags are refused; explicit cross-deck moves go through "Put under…" (`putUnderDeck`, `putUnderPile`, `putUnderChapter`; for a table pile or the cards selected in the Browse panel), which checks `holds`. Revealing the storybook (`revealStory`) sends a Y-card on top face down into the Encounter Bar (`storyToBar`) instead of the revealed pile. Cards the storybook may hold dropped on the face-down storybook (`storyAt`) open the chapter picker (`ChapterDialog`: the cards' backs, Chapter 1–14 and the Epilogue, turned-over chapters disabled via `storyProgress`). Card instructions are never scripted: the app offers generic tools and the player follows the card.
- `areas.ts`: fixed framed areas of the play area (Map, Encounter Bar, Encounter Deck, Character, Storage, Storybook, the four table decks' areas, Actions (id `hand`), Home, Battlefield), which card families each accepts, and `refusal()` for drops. A deck area (`Area.deck`) takes nothing but its deck: `placement()` sends cards dropped anywhere in it onto the deck's pile (refused unless the deck `holds` them all), and callers put them there with `dropOnto()`, which inserts them as the deck's rules say; `Table.tsx` draws the deck's placeholder. The Encounter Deck area has three fixed places (`ENCOUNTER_PLACES`, `encounterPlace()`, `placeStack()`): table stacks with `Stack.place` — `time-passes` and `next-chapter` (both `deck: 'encounter'`) and `used` — that stay when empty and never move; cards dropped anywhere in the area go onto the nearest place (`ontoPlace()`, Encounter Cards only). The time card at the bottom of its place is pinned (`pinned()` in `actions.ts`): every action that takes, reorders or slides cards under a pile leaves it there (`abovePinned`, `underneath`), and dragging a place's `⠿` grip lifts its other cards off as a new pile (`liftPile`). `Table.tsx` draws a Shuffle button below each time card's place (`PLACE_BUTTON`, part of the area's height; `onShufflePlace`), and a Browse button below the Training Deck's (`BROWSE_DECKS`, its area taller for it; `onBrowseDeck` opens the browse panel). Shuffling a table pile goes through `shuffle()` in `App.tsx`, which also sets `shuffled` for a moment: `StackView` then draws copies of its top cards over it that split and slide back (`.shuffle-card`, `SHUFFLE_MS`). Space outside all areas accepts anything. `SPOTS` are card-sized places reserved for one family: nothing else may lie on a spot, and cards of that family dropped near it snap onto it. Spots with `attracts` (the four Region Card places in a 2×2 grid in the Map area — `placement()` picks the one dropped on, else the one the moved card lies on, else the first free one — the Character Card at the top center of the Character area, the Alignment Card half under its left side, the Money Cards half under the right side of the Storage Card) also pull their cards from anywhere on the table; the Storage Card spot (any Y-card), the Encounter Bar row (Y-cards), the Goods rows (Encounter Cards) and the Home area's House Card with its four House Extension places around it (Y-cards) and its Goods and Equipment rows beyond the side extensions (Encounter Cards) don't. A spot with `under` lies beneath the card of the spot beside it (`coveredSide()` says which half is hidden); a spot with `fan` is a row of single cards growing away from its `under` card, every card under the one before as far as the first lies under that card (`shows`, default half): at most `count` of them (Money Cards, so each can be turned to its amount; two House Extensions each side of the House Card, 16 Goods and 4 Equipment in the Home area), or any number with `count: Infinity` (Goods: one row left of the Storage Card, one below it — a spot with the same x as its `under` card runs vertically, `coveredSide()` then says `top`/`bottom`). `fanRow()` takes the piles lined up on a row's line, each at most `FAN_GAP` places beyond the one before. A spot with `fan: { count: 1 }` holds a single card; one with `addsFirst` (the Encounter Bar) takes new cards at the front of its row, on top, its placeholder shown at the place before the first card, drawn under it (`freePlace()`), and once it has cards a second one at the place after its last card, for adding at the end (`freePlaces()`; `spotPlace()` puts a card dropped in line beyond the row there); one with `turn` (the four Market Prices places beside the outer edges of the Region Cards, all but their price strip under them — `MARKET_SHOWS` — Encounter Cards) lays its portrait card landscape, turned a quarter to that side, face up (`faceDown`: face down, the Encounter Bar's Y-cards, turned left so the strip on their back shows) — `settleSpots()` keeps it that way and unrotated, and `flipTop`/`flipStack`/`rotateStack` refuse a pile on it (`turnedSpot()`); one with `over` (the Storybook's Encounter Card, below the revealed cards) lies on top of that storybook slot's card; one with `overlaps` (the Actions area's hand, a column of Y-cards) has no covering card and runs toward that side, each card lying on top of the one before (`growth()` gives any row's direction; `drawOrder()` doesn't reverse it; `freeCovered()` says which side of its free place lies under its last card); one with `upsideDown` (the Actions area's Hand and Discard places) lays its cards turned 180° — `settleSpots()` keeps them so and `rotateStack` refuses them (`upsideDownSpot()`); one with `takesPiles` (the hand, the Encounter Bar) takes a dropped pile and `settleSpots()` spreads it out, one card per place, its top card still on top; one with `slidesUnder` (the Damage Card) takes cards dropped on its pile underneath (`dropOnto()`). The Damage Card itself lies on that spot as a fixed place, `Stack.place: 'damage'` (`addDamagePlace` in `setup.ts`, for new games and old saves): `pinnedOnTop()` keeps it on top for good, as `pinned()` keeps the time cards at the bottom of theirs — actions work on `unpinned()` cards only, and dragging the pile takes nothing (its grip lifts the cards under it). `pinnedOnTop()` likewise keeps a deck's `DeckSpec.keeps` card (Y013 on the Enemy Deck, Y012 on the Training Deck, Y011 on Banned Cards; put there by `addDeckCards` in `setup.ts`, for new games and old saves) on top for good; the Browse panel and Find card don't offer pinned cards (`isPinned()`). A spot takes its family even in an area that doesn't; with `fillsArea`, cards of its family dropped anywhere in its area go to it (the Storybook's Encounter Card, the Encounter Bar, the Actions area's hand). The row's order runs from the covering card outward: `spotPlace()` inserts a dropped card by giving it a position half a unit beside a place, and `settleSpots()` (applied by `store.update` after every change, and by `migrateTable`) closes gaps and snaps the row onto its places (and straightens cards on `turn` spots). `Table.tsx` previews that result while a card is dragged along the row. `drawOrder()` enforces both layerings at render time instead of in `z` (a row under a fanned row lies under its last card). The Battlefield is a grid of landscape Terrain Card places edge to edge (`terrainPlace()`, anchored at the area's own place, `gridOrigin()`), not spots: a pile lying exactly on a grid place belongs to it (`gridPiles()`, `onGrid()`; `measure()` gives it to the Battlefield whatever frame it overlaps). `terrainPlaces()` gives its free places — the first place while it is empty, else a strip (`TERRAIN_STRIP`) along each free side of each card, unless another pile covers the place beyond — and `ontoGrid()` sends Terrain Cards dropped on the Battlefield (or within reach of a strip) to the nearest, one at a time; nothing else goes onto a grid pile. `battlefieldBoxes()` gives the grid's extent and the Enemies place right of it, which frame the area. Terrain Cards are landscape (`isLandscape()`) and only turn around (`rotateStack` by 180°; `StackView` applies `rot` to landscape cards too). `placement()` combines all these rules and returns where dropped cards really go — every way of putting cards on the table uses it. **Area layout.** `AREAS` and `SPOTS` hold each area and spot at its own place (the Map just fits its places; the other sizes only place the areas). The Encounter Bar, Character, Storage, Actions and Home areas (`GROWING`) are framed around their spots (a fanned row as far as its next place, `framedPlaces()`) and the piles belonging to them, with no limit. `measure()` decides which area each table pile belongs to: an area of fixed size containing its center, else the growing frame it overlaps most, starting from the frames as last laid out (`Table.frames`) and taking in piles the frames grow over; `areaForCard()` applies the same rule to a drop. `settleLayout()` (run with `settleSpots()` by `settle()` after every change, in `store.update`, `initialTable` and `migrateTable`) lays the areas out packed (`packedPlaces()`), each exactly `GAP` from the one before, in rows (the Encounter Bar on its own; the Map, the Encounter Deck area and the Storybook, its bottom in line with theirs beside the bar, or down in line with the Map once the bar reaches it; Storage, Character and Actions with the deck areas two by two right of it, `DECK_BLOCK`; Home below Storage and Character and the Battlefield right of Home, each below any area it reaches under, `bottomUnder()`), moving the piles belonging to it, figures on it and its spots by whole units — the own places in `AREAS` / `SPOTS` only fix where spots lie relative to each other; `Table.shifts` records how far each area lies from its own place. Once the player drags an area by the `⠿` tab in the top-right corner of its frame (`moveArea` in `actions.ts`; `Table.tsx` previews the result and snaps with `snapArea()`), `Table.anchors` holds every area's top-left corner and `settleLayout()` lays them out free instead of packed (`anchoredPlaces()`): each at its anchor, top to bottom then left to right, an area in the way of one laid out before it pushed aside to its nearest free side (`pushAside()`), so a growing area pushes its neighbours and they move back as it shrinks; the areas in a dropped area's way get new anchors (`anchorsAfterMove()`). `rearrange()` applies such a change and moves loose piles an area now covers off to the right (figures stay); `resetLayout` deletes the anchors. So spot positions depend on the table: use `spotsOf(t)`, not `SPOTS`, for positions, `allAreas(t)`, not `AREAS`, for frames and hit-testing (both cached per table), and `terrainPlace(t, col, row)` for a battlefield place. **Fit** (`fitView` in `App.tsx`) frames `PLAY_AREAS` (the areas used every round), or `COMBAT_AREAS` while Terrain Cards lie on the Battlefield (`battlefieldInUse()`); pressed again, the whole table.

**UI components.** `App.tsx` wires everything: toolbar, action bar for the selected pile, drop routing between table / sidebar / browse panel (`zoneAt` uses `elementFromPoint` on `data-deck` / `data-dock`), placement (`dropAt` finds a free spot respecting areas and spots, or returns null and notifies when the cards can't go on the table) and dialogs. `Table.tsx` owns all pointer gestures on the canvas (tap, double-tap flip, long-press inspect, drag top card vs. `⠿` grip for the whole pile, one-finger pan, pinch/wheel zoom) and renders areas, stacks, slots and tokens. `Sidebar.tsx`, `Tray.tsx` and the browse panel share `useDragOut.ts` for tap / long-press / drag-out with a floating `CardGhost` (portalled to `body`; `onHover` reports the drag so `App` can light up drop zones). `Tray.tsx` is the right sidebar of cards set aside (setup cards): shown while it holds piles or a drag is over it — `zoneAt` returns a `tray` zone within `TRAY_EDGE` of the table's right edge while it is hidden, and on a tray pile says which pile the drop goes `before`; its width (left-edge handle) and minimized state are per device in `localStorage`. `dialogs.tsx` holds the browse panel (`BrowsePanel`, non-modal, bottom half of the screen, its pile id kept in `browseId` apart from `dialog`; tap selects, only the `⠿` grip drags so swipes scroll, `playCards` / `cardsToDecks` apply drops; opens on the backs; the selection is ordered (tap order) and every action given card ids or indices (`cardsOf`, `playCards`, `cardsToDecks`) moves them in the order given, bottom → top, not in pile order; `⚄ Random` picks N of the filtered cards unseen (`blind`): nothing in the grid marks them, they move face down (`faceUp` of `playCards` / `toTray` / `putUnderPile`) by the bar's own grip) and the modal UIs (card viewer, find card, battlefield builder, chapter picker). `RulesPanel.tsx` is the rulebook drawer (lazy-loaded page images, contents, search) with a second tab for the rule booklets (`Booklets.tsx`: `BookletShelf` of covers, and two reading modes kept in `layout`: `BookletSpread` turning facing pages 2s−1 | 2s, `BookletScroll` one page below the other across the panel, scrolled like the rulebook (`bookletJump` scrolls it to a search hit); the header shows Contents for the rulebook, Shelf and the mode for booklets; `booklets.ts` loads the optional `booklets.json`; search covers both); `rules.ts` maps areas, decks and card types/number ranges to rulebook section ids for the help links — section ids must exist in `rules.json`'s `toc`.

**Setup & migration.** `setup.ts` `initialTable()` builds the rulebook chapter 6.1 setup (shuffled B-Encounters on the Time Passes place, Next Chapter on its own, both time cards face down, sorted Lost Pages/X/Regions/Terrain, storybook in its area, empty campaign decks in theirs, `layDecks`). `migrateTable()` upgrades older saves (decks on the table, free-form sidebar decks, title card, storybook in the sidebar, Storage area a card narrower, cards off their attracting spots, cards left in the removed hand, Home area before it moved down below the taller Storybook area, Map area before it shrank around its places and the Encounter Bar moved left, Y-cards in the Encounter Bar before it became a row and the areas below it before they moved up for the lower bar (`fillBar`, `raiseAreas`; older migrations work in those older coordinates, `RAISE`), the campaign decks in the sidebar before they got their areas (`layDecks`, `clearDeckAreas` moves piles off the new areas), areas laid out near their own places before they were packed (`packAreas` moves loose piles and figures an area now covers off to the right), the Encounter Deck and Time Card sidebar decks before the Encounter Deck area (`OLD_ENCOUNTER` kept through `migrateDecks`; `addEncounterArea` parks the new area past everything until `layEncounterDeck` lays out its places and cards), the Actions area (`addHandArea` parks it likewise until `packAreas` lays it out), the Battlefield area (`addBattlefieldArea` parks it likewise, and moves the Terrain Cards of a battlefield built before, `Table.battlefield`, onto its grid) — `Table.layout` (`LAYOUT`) marks saves already laid out for the current areas) — when changing the `Table` shape, extend it so existing saves on the tablet keep working, and keep `isValidTable` in `App.tsx` consistent (every playable card exactly once).

**Access code.** `middleware.ts` (Vercel Routing Middleware, deployment only) serves a code form until the request carries the `gw-access` cookie, a SHA-256 of the `ACCESS_CODE` environment variable set in the Vercel project (never commit the code). The manifest and icons stay open (fetched without cookies). The service worker caches only `ok` navigations, so the form never becomes the offline page.

**PWA.** `public/manifest.webmanifest` + `public/sw.js` (registered in `main.tsx`, production only). The service worker is hand-written: navigations network-first with the cached `/` as offline fallback, all other same-origin GETs cache-first and cached on first use (bump `CACHE` when files change under the same name, e.g. regenerated card data).

## Conventions

- Put game rules in `decks.ts` / `areas.ts` / pure functions in `actions.ts`, not in components; components call `update(...)` and show feedback with `notify(...)` (refusals) or `notify(text, true)` (success).
- Any new way of placing cards on the table or into decks must go through the same checks as drag-and-drop (`placement` for the table, `holds` / `homeDeck` for decks).
- Style tokens are CSS variables in `styles.css`; world-space elements (areas, stacks) use world-unit sizes, screen-space UI uses ≥44 px touch targets.
- Commit messages follow Conventional Commits: `type(scope)!: description`, lower-case imperative description, the body explaining the why as before. Types: `feat` (player-visible feature), `fix`, `perf`, `refactor`, `docs`, `style`, `test`, `build`, `ci`, `chore`, `revert`; only `feat`, `fix`, `perf` and `revert` appear in the changelog, so write their descriptions for the player. Scopes are optional, by part of the app: `areas`, `battlefield`, `browse`, `decks`, `encounter-bar`, `figures`, `rules`, `search`, `sidebar`, `storybook`, `tray`, `save` (saves/migration), `pwa`, `deploy`, `scripts`. A change that breaks old saves or removes a feature gets `!` and a `BREAKING CHANGE:` footer. `.githooks/commit-msg` (enabled by `npm install` through `prepare`) refuses other messages.
- Versions follow SemVer (`package.json`, tags `vX.Y.Z`); `CHANGELOG.md` is generated by `npm run release` from the commits since the last tag (entries up to 0.5.0 were written by hand from the earlier, non-conventional commits). Don't edit released sections by hand except to fix wording.
- The project also has an OpenSpec setup (`openspec/`, `/opsx:*` commands) for spec-driven changes; no specs exist yet.
